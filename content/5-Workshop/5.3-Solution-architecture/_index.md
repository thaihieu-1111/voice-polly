Before deploying AWS resources, we need to understand the overall architecture of the Polly Voice application and how AWS services work together throughout the system.

The application is built using a **Serverless** architecture, where the entire infrastructure is managed by AWS. This approach eliminates the need to provision and manage servers while providing automatic scaling, high availability, and cost optimization.

---

## 5.3.1 Overall Architecture

The Polly Voice application consists of three main layers:

* Frontend Layer
* Backend Layer
* Storage Layer

The frontend is deployed on **AWS Amplify**, which provides the user interface.

The backend consists of **Amazon API Gateway** and **AWS Lambda**, which process user requests and communicate with other AWS services.

The application supports two main features:

* **Text-to-Speech (TTS):** Converts text into speech using **Amazon Polly**.
* **Speech-to-Text (STT):** Converts speech into text using **Amazon Transcribe**.

Generated or uploaded audio files are stored in **Amazon S3**, while the conversion history for both features is stored in **Amazon DynamoDB**.

User authentication is handled by **Amazon Cognito** before requests are allowed to access the backend system.

## 5.3.2 AWS Services Used

The Polly Voice application uses several AWS Managed Services. Each service is responsible for a specific function within the system.

### AWS Amplify

AWS Amplify is used to deploy the React application.

It automatically deploys the frontend from the GitHub repository and provides secure HTTPS hosting with a built-in CI/CD pipeline.

---

### Amazon Cognito

Amazon Cognito is responsible for user authentication and user management.

Its main features include:

* User registration.
* User sign-in.
* JWT token generation.
* User session management.

Only authenticated users are allowed to access the application's APIs.

---

### Amazon API Gateway

Amazon API Gateway provides REST APIs for the frontend.

Instead of allowing the frontend to invoke Lambda directly, all requests are routed through API Gateway.

API Gateway also validates JWT tokens issued by Amazon Cognito before forwarding requests to AWS Lambda.

---

### AWS Lambda

AWS Lambda contains the entire business logic of the application.

After receiving requests from API Gateway, Lambda performs tasks such as:

* Validating input data.
* Calling Amazon Polly to convert text into speech.
* Calling Amazon Transcribe to convert speech into text.
* Uploading audio files to Amazon S3.
* Saving conversion history to Amazon DynamoDB.
* Returning results to the frontend.

Since Lambda follows the Serverless computing model, compute resources are allocated only when requests are received.

---

### Amazon Polly

Amazon Polly converts text into natural-sounding speech.

Users can choose from multiple voice options before generating speech.

After processing is complete, Amazon Polly returns an audio stream that Lambda saves as an MP3 file.

---

### Amazon Transcribe

Amazon Transcribe converts speech contained in audio files into text.

After a user uploads an audio file, AWS Lambda sends a request to Amazon Transcribe to perform speech recognition.

Once processing is complete, Amazon Transcribe returns the transcription result, which Lambda forwards to the frontend.

---

### Amazon S3

Amazon S3 stores all audio files used by the application.

For the **Text-to-Speech** feature, Lambda uploads MP3 files generated by Amazon Polly to S3.

For the **Speech-to-Text** feature, audio files uploaded by users are also stored in S3 so that Amazon Transcribe can process them.

Centralized storage in Amazon S3 makes it easier to manage, play back, and download audio files.

---

### Amazon DynamoDB

Amazon DynamoDB stores the conversion history for every request.

The stored information includes:

* User ID.
* Conversion type (Text-to-Speech or Speech-to-Text).
* Input text or transcription result.
* Selected voice (for TTS).
* Audio file location.
* Creation timestamp.

Separating history data from audio files makes the system easier to query and manage.

## 5.3.3 Data Processing Flow

The application supports two primary processing workflows: **Text-to-Speech (TTS)** and **Speech-to-Text (STT)**.

### Text-to-Speech (TTS) Workflow

#### Step 1

The user accesses the Polly Voice application deployed on AWS Amplify.

---

#### Step 2

The user signs in using Amazon Cognito.

After successful authentication, Cognito returns a JWT token.

---

#### Step 3

The frontend sends a Text-to-Speech request to Amazon API Gateway together with the JWT token.

---

#### Step 4

API Gateway validates the JWT token.

If the token is valid, the request is forwarded to AWS Lambda.

Otherwise, the request is rejected.

---

#### Step 5

AWS Lambda sends the input text to Amazon Polly.

Amazon Polly synthesizes the speech and returns an audio stream.

---

#### Step 6

Lambda uploads the generated MP3 file to Amazon S3.

---

#### Step 7

Lambda stores the conversion history in Amazon DynamoDB.

---

#### Step 8

Lambda returns the audio file location together with the conversion information to the frontend.

---

#### Step 9

The frontend allows users to:

* Play the audio file.
* Download the MP3 file.
* View previous conversion history.

---

### Speech-to-Text (STT) Workflow

#### Step 1

The user accesses the Polly Voice application on AWS Amplify and signs in using Amazon Cognito.

---

#### Step 2

The frontend sends a Speech-to-Text request to Amazon API Gateway together with the JWT token and the uploaded audio file.

---

#### Step 3

API Gateway validates the JWT token.

If the token is valid, the request is forwarded to AWS Lambda.

---

#### Step 4

AWS Lambda uploads the audio file to Amazon S3.

---

#### Step 5

Lambda sends a request to Amazon Transcribe to perform speech-to-text conversion.

---

#### Step 6

Amazon Transcribe processes the audio file and returns the transcription result.

---

#### Step 7

Lambda stores the conversion history in Amazon DynamoDB.

---

#### Step 8

Lambda returns the transcribed text to the frontend.

---

#### Step 9

The frontend displays the transcription result so that users can view, copy, or continue using it.

## Advantages of the Architecture

The selected architecture provides several benefits for the application.

### Fully Serverless

There is no need to manage servers or operating systems.

AWS automatically provisions computing resources whenever user requests are received.

---

### Secure Authentication

Amazon Cognito authenticates users before backend resources can be accessed.

JWT tokens help prevent unauthorized API requests.

---

### High Scalability

AWS Lambda automatically scales based on the number of incoming requests.

Amazon S3, Amazon DynamoDB, and Amazon Transcribe also provide automatic scaling without manual configuration.

---

### Cost Optimization

All core AWS services follow a **Pay-as-you-go** pricing model, meaning costs are incurred only when the application is being used.

This architecture is well suited for small to medium-sized cloud-native applications.
